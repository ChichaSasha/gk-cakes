## Mapping conventions

The registry below maps **every extracted decision** (including conflicts/examples)
to a typed field or design consequence. It inherits the constraints, permissions,
versioning and planned acceptance cases of its named profile below. Status remains
in JSON; an unresolved field cannot become executable by appearing in this table.
For each registry row, the exact value is at the linked file's JSON Pointer
`/decisions/<key>/business/value`; conditions/exceptions/unresolved semantics are
siblings, provenance is `/decisions/<key>/provenance`. ID is `BO-GK-NNN.<key>`.

Use ordinary typed entities and relationships. The context JSON is **not** a
production key/value store. No generic `settings(key,jsonb)` proposal. A single
immutable accepted-quote/order document may use JSONB as a justified presentation
snapshot, with schema/version/hash and safe fields; queryable money, policy IDs,
allergens, schedule resources and customer relationships remain typed/relational.
Private bank documents live in protected object storage; database stores authorized
object references, not public URLs or document contents in audit logs.

Every policy/content version needs UUID PK, source decision ID(s), input hash,
recorded-at `timestamptz`, recording actor, business approver/evidence when required,
and change reason. Operational effective-from is **unknown**, not the comment date.
Resolve activation/effective date before launch. A successor preserves its predecessor;
no silent overwrite of earlier evidence or accepted order snapshots.

Runtime staff permissions come from K00/local staff roles, not Trello membership.
For every proposed admin write below, exact staff capability/authority and policy
editability need GK-018/021 review unless already explicitly specified in K00.
Owner permission to state a business rule does not authorize arbitrary staff to edit
it. No owner-supplied numeric value is automatically an editable admin setting.
